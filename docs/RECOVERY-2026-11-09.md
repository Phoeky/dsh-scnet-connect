### ⚠️ 踩坑记录：`--dump-config` 不校验必填项

第一版补丁把 `webserver` 的 config 整块替换成只有 `port: 11256`，`--dump-config` 照样 exit 0、零告警，但真机启动直接崩：

```
webserver (required)  ValidationError: invalid config: $.host missing required value (at host)
→ webServer 服务永不就绪，连带 5 个插件挂起（web-runtime/open-in-app/directory-picker/harness-dev-context/client-hmr）
崩溃日志：%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-<ts>-host.log
```

原因：非 insert 补丁是**整块替换** config，而 `@deepseek-ai/dsh-host-webserver` 的 `host` 为必填、无默认值。修法是把默认配置字段一并显式写出，只改 port：

```yaml
- id: webserver
  name: "@deepseek-ai/dsh-host-webserver"
  config:
    host: 127.0.0.1
    port: 11256
    compression: gzip
    compressionLevel: 1
    compressionThresholdBytes: 1024
```

结论：**profile 补丁必须靠真实启动验证，`--dump-config` 只能查语法与组合顺序。** 隔离验证的正确姿势是把 profile 复制到临时 `DSH_HOME`（`cp -r` 后需 `CI=true dsh plugin --profile <copy> install` 补回符号链接），改一个不同的端口（如 11257）避免与真机冲突，然后直接 `dsh --profile <copy>` 起一次，看到 `dsh web: http://127.0.0.1:11257/?token=...` 才算通过。

修好后实测：副本启动成功，`GET /` → 401、带 token → 303；插件激活并写出 `scnet-connect-status.json`（`registered: true`、provider `scnet`、模型 `SCNet-Max`）。
